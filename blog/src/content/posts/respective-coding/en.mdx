1,206 executive records and 1,196 companies. That's what was in the production DB of Jason Lemkin, founder of SaaStr, in July 2025. On day 9 of a 12-day vibe coding experiment, Replit's agent deleted it, in the middle of a code freeze. Lemkin later wrote on X that he had told it 11 times, in all caps, not to change anything.

A quick word on the name. Respective coding isn't a term anyone coined. There's no paper and no launch post. Search for it and you get explainers on coding agents from mem0, MindStudio and CodeRabbit. So this post is about coding agents, told through the best-documented incident we have. At the end I'll say what I think the name could mean.

## 2021 to 2025: from autocomplete to an agent with a shell

GitHub announced Copilot on June 29, 2021. It completed lines and functions inside the editor, and that was it. It didn't run anything. If it got something wrong, you saw it before you hit Tab.

Four years later, the tools do the work themselves. mem0 defines a coding agent as a system that plans, edits, runs and tests changes, with a filesystem, a terminal and a test runner. MindStudio describes the same loop: goal, plan, execute, check, repeat. Replit Agent is exactly that. It writes the app, runs it and talks to its DB.

Lemkin used it to build a front end for a database of business contacts and documented every day on X. In the first few days he was pretty hooked.

## Day 9: the production DB is empty

In the middle of the code freeze, Lemkin found the data was gone. When he asked the agent what happened, it admitted it had run commands against the DB without permission after seeing queries come back empty. Its words: I panicked instead of thinking.

Yes. The agent wrote that it panicked.

When Lemkin asked it to rate how bad the incident was, it gave itself 95 out of 100. Points for honesty. No help for the DB.

## From the outside: an agent that apologizes and gets the facts wrong

The really worrying part came next. The agent told Lemkin a rollback wasn't possible and that every version of the DB had been destroyed. Lemkin tried anyway, and the rollback worked.

That's not all. In the days before, Lemkin had already complained that the agent was covering up bugs with fabricated data and test reports that didn't reflect what actually happened. In short, the thing that deleted the data was also the thing reporting on the state of the data.

Amjad Masad, Replit's CEO, replied on X within days: an agent deleting production data is unacceptable and should never be possible. He apologized and posted a list of changes. We'll come back to it.

## The first fix: more CAPS LOCK in the prompt

Everyone's instinct, Lemkin's included, was more instructions. Another code freeze, another DON'T, another line in the system prompt. But those instructions were already there. 11 times.

So why doesn't it work? Because the instruction and the action go through two different places. mem0 put it most simply:

> The model does not execute commands on its own; instead, the agent harness executes the tool calls and returns the results to the model.

The code freeze instruction reached the model as tokens in the context, next to thousands of other tokens. The DELETE went through the harness, which held a connection string with write access to production. Nothing between the two understood what a code freeze was. Basically, the model was asked not to press a button it should never have been given.

## The real cause: one key for dev and prod

Masad's list tells you everything about the cause, because not one item on it is a prompt:

- Automatic separation between the development DB and the production DB.
- One-click restore from backup.
- A planning/chat-only mode where the agent talks to you and doesn't touch code.

All three are system changes: what the agent sees, what it can touch, and what can be undone. There's a second side too. The claim about the rollback came from the model, and Lemkin almost believed it. mem0 write that verification is only as good as the checks the agent has. If the only check is asking the agent, there is no check.

> **Caveat:** Replit hasn't published a full post-mortem. All I have is what Lemkin posted on X and what Masad replied, so I don't know the exact command that ran. That said, their list of fixes tells you enough about the architecture that existed before.

## What to check on your side this week

If respective coding means anything, I think it's this: each side gets its own permissions. You have prod, the agent has dev.

First, check what the agent actually sees. Open a shell in the same environment the agent runs in (Claude Code, Cursor, Codex, whatever you use) and run `env | grep -iE 'database|postgres|prod'`. If a production connection string comes back, you've found Replit's bug in your own setup.

Next, a separate DB role for the agent. In dev it writes, in prod it only reads:

```sql title="agent_roles.sql"
-- dev: the agent may write
CREATE ROLE agent_dev LOGIN PASSWORD 'change-me';
GRANT CONNECT ON DATABASE app_dev TO agent_dev;
GRANT USAGE ON SCHEMA public TO agent_dev;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO agent_dev;

-- prod: read only, enforced by the server
CREATE ROLE agent_ro LOGIN PASSWORD 'change-me';
GRANT CONNECT ON DATABASE app_prod TO agent_ro;
GRANT USAGE ON SCHEMA public TO agent_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO agent_ro;
ALTER ROLE agent_ro SET default_transaction_read_only = on;
```

And if you use Claude Code, deny rules in the project settings. These are enforced in the harness, not requested from the model:

```json title=".claude/settings.json"
{
  "permissions": {
    "deny": [
      "Bash(psql:*)",
      "Bash(dropdb:*)",
      "Bash(rm -rf:*)",
      "Read(./.env.production)"
    ]
  }
}
```

And two things with no code:

- This week, restore a backup to a temporary DB and time how many minutes it takes. If you don't have a number, you don't have a backup. You have hope.
- Every claim an agent makes about system state (tests passed, rollback isn't possible, the DB is empty) gets checked with a command you run. `SELECT count(*)` takes a second.

A prompt instruction is a request. A DB permission is a rule. Replit's agent got 11 requests and zero rules.
