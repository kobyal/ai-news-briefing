## A million lines, none by hand

In late August 2025, a team at OpenAI opened an empty repo and set one rule: no human writes a line of code. Not logic, not tests, not CI, not docs. Codex writes all of it.

Five months later the repo has about a million lines of code and 1,500 merged PRs. The team started with three engineers and now has seven. They average 3.5 PRs per engineer per day, and that number went up as the team grew. They estimate the work took a tenth of the time it would have taken by hand. Even the first AGENTS.md, the file that tells agents how to work in the repo, was written by Codex.

These are their numbers about their own product, so take them with a grain of salt. The number isn't the point of the post, though. This sentence is: the team's job is no longer to write code. It is to design the environment, define intent, and build feedback loops that let agents work reliably. They call that harness engineering.

## Who coined it? Depends who you ask

Addy Osmani writes that Viv Trivedy coined the term, and that Trivedy's post "Anatomy of an Agent Harness" is the cleanest definition out there. The Habitat Thinking docs credit Birgitta Böckeler of ThoughtWorks, for her piece on martinfowler.com. Dex Horthy and HumanLayer were tracking the same pattern even earlier.

So nobody invented it alone. It showed up in several places at once and stuck. That's a good sign, not a bad one.

Trivedy's line does most of the work: Agent = Model + Harness. If you're not the model, you're the harness.

## What's in a harness, and what isn't

A harness is all the code, config, and runtime logic that isn't the model itself. The system prompt, the tools, how context is managed, hooks, the sandbox, subagents, checks, and what happens when something fails halfway through. A raw model is not an agent. It becomes one when someone gives it state, tool execution, feedback, and constraints that can actually be enforced.

Lilian Weng contrasts this with 2023. Back then an agent was "LLM + memory + tools + planning." A harness adds workflow, evals, permissions, and state that persists across runs. That's not prompt templates anymore. It's runtime design.

What it isn't:

- It's not prompt engineering with a new name. The prompt is one component out of ten.
- It's not a framework. You can build a harness on any SDK, or on no SDK at all.
- It doesn't make the model smarter. The walkinglabs course says it plainly: the harness doesn't improve the model, it builds a closed working system around it.

## Osmani's rule: every mistake, once

The mechanism is simple. Osmani puts it like this: every time the agent makes a mistake, you spend the time to engineer a fix so it never makes that mistake again. Ever.

In practice it looks like this. The agent imported from a directory it shouldn't touch? Add a lint rule, not another line in the prompt. It declared "done" with red tests? Add a hook that won't let a task close without green CI. It forgot a convention? That goes into AGENTS.md, and the next agent reads it at the start of every session.

The harness tightens with every screwup. Wait, isn't this just the old test harness? Almost. Böckeler noticed that AI-written code doesn't break loudly. It compiles, passes tests, and slowly erodes the codebase. Conventions get forgotten, mistakes repeat. The degradation is quiet. So the harness has to check architecture, naming, and security too, not just whether a function returns the right value.

HumanLayer go further and say most agent failures are a configuration skill issue, not a model issue. Osmani closes the loop: a decent model with a great harness beats a great model with a bad harness.

## Our pipeline: the harness is most of the code

The aibriefing.dev pipeline has run every morning since May 2026. About 10 agents, a merger step that combines them, and a QA evaluator that runs after publish and flags P0s. When I look at the repo, the part that actually talks to the model is small. Everything else is harness.

One example: our `claude -p` wrapper retries transient errors and repairs broken JSON. A small, boring loop. It closed three production incidents. None of them was "the model gave the wrong answer." They were a timeout, JSON with a prose preamble, and an empty response reported as success.

That's what surprised me most. Our worst bugs were silent failures, not wrong answers. The agent doesn't fail loudly. It returns `{}` and says success. Without a check that runs afterward, you find out from your users.

One more thing, boring and good: we used to copy logic between agents, and a fix that landed in one copy didn't land in the other. Today it lives in `shared/`, with one wrapper for everyone. That's harness too.

## When not to build your own

Rajit Khanna built a media-generation agent at prismvideos on the Vercel SDK. It worked well. A few days later a competitor, Higgsfield, launched an agent with cross-session memory, skills, automations, and a filesystem. All of it on Hermes, an open agent from Nous Research with more than 185k GitHub stars.

What did they do? Deleted their agent. They stood up an EC2 box with a Hono server, one Hermes container per customer, and feed it only what's unique to them: the system prompt, tools over MCP, skills, and connectors to Meta Ads and Google Drive.

This doesn't contradict everything above. It sharpens it. There's the generic harness: session management, compaction, memory, a browser. You're probably better off taking that off the shelf. And there's your domain harness: the checks that know what valid output means for you, the permissions, the rules born from your own screwups. Nobody will build that for you.

## What to try this week

If you don't have an AGENTS.md, start one. Then go through your agent's last five mistakes and ask of each: can this become an automated check? Lint, schema, hook, test. Only what can't become a check goes into the prompt.

And if nothing runs after your agent says "done," start there. The agent will always say it's done.
