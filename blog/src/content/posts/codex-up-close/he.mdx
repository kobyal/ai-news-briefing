ב-1 בספטמבר 2026 סיימון וויליסון עשה מה שכולנו עושים פעם בחצי שנה. הוא פתח את OmniDiskSweeper כדי לראות מה אוכל לו את הדיסק. בתוך `~/.cache/` הוא מצא תיקייה בשם `codex-primary-runtime`, ‏1.7GB. בפנים היו Python מלא, Node.js מלא, git, Poppler ועותק שלם של LibreOffice. כל זה הותקן בשקט יחד עם אפליקציית הדסקטופ של Codex, שבינתיים שינתה את השם שלה פשוט ל-ChatGPT.

התיקייה הזאת מראה יפה איפה Codex עומד היום. ה-CLI יצא באפריל 2025 ככלי קטן לטרמינל. שנה וחצי אחרי, OpenAI מתקינה אצלכם runtime שלם, כדי שה-agent יוכל לפתוח spreadsheet, לקרוא PDF ולהריץ טסטים בלי לשאול מה מותקן לכם. ובמספרים: יותר מ-3 מיליון מפתחים בשבוע באפריל, ויותר מ-4 מיליון במאי. זה כבר לא ניסוי.

בחלק הראשון של הסדרה נבדוק מה באמת יש שם, כמה זה עולה, ואיך זה מול Claude Code ביום-יום.

## מה זה Codex בסוף 2026, ומה הוא לא

בגדול, Codex הוא agent אחד עם חמש כניסות, וכולן מחוברות לחשבון ה-ChatGPT שלכם. יש CLI בקוד פתוח (Apache 2.0, ב-`github.com/openai/codex`) ותוסף ל-IDE (VS Code והמשפחה שלו). יש אפליקציית דסקטופ ל-Mac ול-Windows. יש Codex בענן דרך `chatgpt.com/codex`, עם סביבה קבועה לכל repo. ומאז 14 במאי יש גם אפליקציה במובייל. שיחה שפתחתם בטרמינל זמינה בטלפון, ו-agent שרץ בענן ממשיך לעבוד גם אחרי שסגרתם את הלפטופ.

מה הוא לא: הוא לא המודל Codex מ-2021 שהריץ את Copilot הראשון. זה אותו שם ומוצר אחר לגמרי, כי OpenAI פשוט ממחזרת שמות. הוא גם לא IDE כמו Cursor. והוא לא מוצר API שמשלמים עליו לפי טוקן, לפחות לא כברירת מחדל. Codex כלול במנוי ChatGPT, ו-API key הוא אופציה ולא הדרך הראשית.

## ידיים על המקלדת: מה רואים כשמתקינים

ההתקנה של ה-CLI לוקחת דקה:

```bash title="install.sh"
npm i -g @openai/codex        # or: brew install --cask codex
codex                         # TUI, sign in with ChatGPT
codex exec "run the tests and fix what fails"   # headless, for CI
codex resume                  # back to a previous session
```

בהרצה הראשונה הוא שואל אם לסמוך על התיקייה, ומראה באיזה מצב הרשאות הוא רץ. משם עובדים עם slash commands. `/init` כותב `AGENTS.md`, קובץ ההוראות של הפרויקט. `/model` בוחר מודל ורמת reasoning. `/review` עובר על ה-diff הנוכחי כמו reviewer. `/approvals` קובע מתי הוא עוצר לשאול, ו-`/status` מראה כמה נשאר לכם מהמכסה.

את רוב ההחלטות החשובות שמים בקובץ אחד:

```toml title="~/.codex/config.toml"
model = "gpt-5.3-codex"
model_reasoning_effort = "medium"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = false

[mcp_servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
```

השורה שהכי שווה להבין היא `sandbox_mode`. ב-`workspace-write` הוא כותב רק בתוך ה-repo, ובלי רשת. זה sandbox ברמת מערכת ההפעלה ולא בקשה מנומסת ב-prompt. תשאירו את זה ככה, ותפתחו רשת רק למשימה שבאמת צריכה אותה.

בענן הזרימה אחרת. מחברים repo, מגדירים סביבה (setup script ומשתני סביבה), ושולחים משימה מהדפדפן או מהטלפון. ב-GitHub אפשר לכתוב `@codex review` בתגובה על PR ולקבל review אוטומטי. ככה רוב הצוותים מתחילים, ובצדק.

## המספרים: כמה זה עולה ואיפה נגמרת המכסה

Codex כלול במנוי ChatGPT. Plus עולה $20 לחודש ו-Pro עולה $200, ולארגונים יש Business ו-Enterprise. אין מחיר נפרד ל-Codex, ו-OpenAI גם לא מפרסמת מספר הודעות קבוע. המכסה תלויה בגודל המשימה ומתאפסת בחלונות זמן. משימת ענן שורפת ממנה יותר מעריכה קטנה מקומית. בפועל, `/status` הוא המקור היחיד שאפשר לסמוך עליו.

המודלים:

- **GPT-5.3-Codex** (5 בפברואר 2026): לפי OpenAI הוא מהיר ב-25% מ-5.2-Codex. הוא קבע שיא ב-SWE-Bench Pro וב-Terminal-Bench 2.0, עם פחות טוקנים לכל משימה. אלה המספרים שלהם, על ה-benchmarks שהם בחרו.
- **GPT-5.3-Codex-Spark** (12 בפברואר): מודל קטן שרץ על חומרה של Cerebras. הוא מוציא יותר מ-1,000 טוקנים לשנייה, עם context של 128k, טקסט בלבד. הוא זמין כ-research preview למנויי Pro, עם מכסה נפרדת שלא נספרת מהרגילה.

ויש עוד שני מספרים, פחות רציניים. 1.7GB בדיסק בשביל אפליקציית הדסקטופ. ו-$230 בשביל Codex Micro, מקלדת שהשיקו עם Work Louder ביולי. יש לה כפתור סיבובי לרמת ה-reasoning ונורות RGB שמראות איזה agent חושב ואיזה מחכה לכם. היא אזלה מהמלאי. כן.

## איפה הוא באמת חזק

קודם כל, עבודה ארוכה בלי השגחה. OpenAI הראו את GPT-5.3-Codex בונה משחקים מאפס לאורך מיליוני טוקנים, עם prompts גנריים כמו "fix the bug". בעבודה אמיתית זה אומר שאפשר לשלוח לו refactor של שעה בענן ולחזור לתוצאה.

חוץ מזה, code review. פה העדויות הכי ספציפיות. ב-Duolingo אומרים שרק הוא תפס בעיות backward compatibility ב-benchmark הפנימי שלהם ל-code review ב-Python. ב-Ramp אומרים שה-reviews שלו תופסים באגים שהצוות היה מפספס. וב-Wonderful הישראלית הלכו הכי רחוק:

> "At Wonderful, Codex CLI has completely replaced every other agentic harness for our core technology and architecture work requiring deep reasoning and understanding." — Daniel Sikorskiy, Chief Architect, Wonderful (openai.com/codex)

ובמקביל יש את כל מה שמסביב. ה-sandbox דולק כברירת מחדל, ואת הקוד של ה-CLI אפשר לקרוא. פקודות מאשרים מהטלפון דרך relay שלא חושף את המחשב לאינטרנט. מאז 16 באפריל נוספו גם computer use ברקע, דפדפן מובנה שאפשר לכתוב הערות ישירות על הדף שלו, ויותר מ-90 plugins חדשים (Atlassian Rovo, CircleCI, CodeRabbit, GitLab Issues, Neon, Render ועוד).

## איפה הוא נופל

קודם כל, השמות. Codex הוא מודל, CLI, אפליקציה (שעכשיו נקראת ChatGPT), סוכן ענן, מוצר אבטחה (Codex Security, מרץ 2026) ומקלדת. נסו להסביר לצוות ה-security מה בדיוק אישרתם.

המכסה אטומה. בלי מספר מפורסם קשה לתכנן עבודה של צוות. מי שמריץ כמה agents במקביל יגלה את הגבול באמצע היום ולא בתיעוד.

הפיצ'רים החדשים מכוונים מאוד ל-Mac. OpenAI מתארים את ה-computer use ברקע כעבודה "on your Mac", חיבור ל-devbox ב-SSH עדיין ב-alpha, ו-Spark זמין רק ב-Pro. ולפי OpenAI עצמם, Spark עושה עריכות מינימליות ולא מריץ טסטים אם לא ביקשתם. כלומר הוא מהיר, אבל לבדוק זה שוב עליכם.

והאפליקציה מתקינה runtime של 1.7GB בלי לשאול. אצל מפתח בודד זה ניטפוק. במחשב ארגוני מנוהל זה Python ו-Node נוספים שה-IT לא יודע עליהם.

> **הסתייגות:** את כל ה-benchmarks בפוסט הזה OpenAI פרסמה על המודלים של עצמה. אני לא קונה "שיא חדש" בלי להריץ על ה-repo שלי, ואני ממליץ גם לכם לא לקנות. העדויות של הלקוחות מעניינות יותר, אבל גם הן מופיעות בדף שיווק.

## Codex מול Claude Code, ביום-יום

על הנייר הם כמעט אותו דבר. שניהם agent בטרמינל, ושניהם קוראים קובץ הוראות לפרויקט ומדברים MCP. לשניהם יש מצב headless (`codex exec` מול `claude -p`), ושניהם מתחילים ב-$20 לחודש. ההבדלים צצים אחרי שבוע של עבודה.

אז איפה בדיוק? Codex חזק בכל מה שקורה כשאתם לא ליד המחשב: ענן, מובייל ו-sandbox שלא צריך להגדיר. גם לאנטרופיק יש Claude Code בדפדפן. אבל ב-Codex הענן, המובייל וה-review ב-GitHub הם מוצר אחד שרץ מאותו חשבון. Claude Code חזק בשליטה על הלולאה עצמה. יש לו hooks שרצים לפני ואחרי כל כלי, subagents, והרשאות מפורטות ב-`settings.json`. רוצים שכל עריכה תעבור linter לפני שה-agent ממשיך? ב-Claude Code זה hook אחד. ב-Codex זה עדיין יותר הוראה ב-`AGENTS.md` מאשר אכיפה.

טיפ קטן למי שמריץ את שניהם על אותו repo. Codex קורא `AGENTS.md` ו-Claude Code קורא `CLAUDE.md`. תחזיקו קובץ אחד ותריצו `ln -s AGENTS.md CLAUDE.md`, אחרת תוך שבועיים יהיו לכם שתי גרסאות שונות של ההוראות.

## מי צריך לבחור בו הרבעון

אם יש לצוות שלכם כבר מנוי ChatGPT, לנסות את Codex לא עולה לכם כלום. אין סיבה לא להפעיל `@codex review` על repo אחד כבר השבוע. אם רוב העבודה שלכם היא משימות ארוכות שאפשר לשלוח ולשכוח, או שאתם רוצים לאשר פקודות מהטלפון, כרגע הוא המוצר המלוטש יותר. ואם בניתם workflow על hooks ו-subagents ב-Claude Code, אין פה סיבה לעבור. תריצו את שניהם במקביל ותראו.

מה לעשות השבוע:

1. תריצו `npm i -g @openai/codex` ואז `codex` על repo אמיתי, ב-branch נפרד.
2. קחו טסט אחד שנופל, ותריצו את אותו prompt ב-`codex exec` וב-`claude -p`. תמדדו זמן, גודל diff, וכמה פעמים הייתם צריכים להתערב.
3. תפעילו `@codex review` על repo אחד לשבועיים, ותספרו כמה הערות היו באגים אמיתיים וכמה היו רעש.
4. תפתחו את `~/.codex/config.toml` ותוודאו ש-`network_access = false` נשאר ברירת המחדל.

בסוף מנצח הכלי שהטסטים שלכם תופסים אצלו פחות טעויות. ה-benchmark פחות חשוב.
