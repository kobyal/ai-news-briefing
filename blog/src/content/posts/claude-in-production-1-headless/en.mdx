38 minutes. That's how long a single `claude -p` call sat on September 8, 2026. There was no error and no log line, because the Mac went to sleep on battery. In a chat you'd see the cursor wasn't moving. In a pipeline that starts at 06:07 in the morning, nobody's looking.

For us, `claude -p` isn't a chat. It's a pipeline step. We run about 10 agents daily, and have since May 2026. All of them call Claude through one wrapper: `shared/anthropic_cc.py`. In this part I'll go through what it takes for this to hold up while you're still asleep: who pays, which output format to use, when to retry, how to fix broken JSON, what to do about a hook that blocks you, and why a timeout alone won't save you. Part 2 covers the failures that don't throw an error at all.

## 01 · Decide who pays: subscription or API key

`claude -p` (or `--print`) runs the same Claude Code agent loop, prints an answer and exits. There's no UI and no permission prompts. Anthropic's docs say it directly:

> To drive the same agent loop from a language other than Python or TypeScript, run the CLI as a subprocess with the `-p` flag and `--output-format json`.
> — Agent SDK overview, Claude Code Docs

Wait, we write Python. So why a subprocess and not the Agent SDK? The reason is money and auth, not technology. The "Hack: claude -p" post on laughingmeme.org from March 20, 2026 put it best. The CLI is already running on your machine and already has auth and a budget, and all your LLM spend sits on one line of the invoice. The post ends with "Probably this is what the agent sdk is for? This worked."

In practice this is an economic decision. On the API you pay per token. Sonnet 4.5 costs $3 for input and $15 for output per million tokens, and Opus 4.5 costs $5 and $25 (MindStudio's numbers). On a subscription you pay a flat fee, but the terms move. XDA reported on May 13, 2026 that subscriptions no longer include Agent SDK and `claude -p` usage. So check your plan's terms this month, not what was true in the spring. We run the heavy writing on the subscription and translation and classification on cheaper models. Anything a rule can do, we do with a rule.

One gotcha cost us. If the subprocess inherits `CLAUDE_CODE_*` variables from the session that launched it, subscription auth breaks and you get an error about your credit balance. It has nothing to do with your balance. Strip those variables before the call.

## 02 · json output, not text

The laughingmeme hack uses `--output-format text` and checks `returncode == 0`. That's enough for a one-off script. It's not enough for a pipeline. With `json` you get an envelope: `result` (the model's text), `is_error`, `subtype`, `num_turns`, `duration_ms`, `total_cost_usd` and `session_id`. That gives you three things right away: a per-call cost for the log, an error flag that doesn't depend on the exit code, and a split between the metadata and the answer itself.

```bash title="step.sh"
claude -p --output-format json --model sonnet < prompt.txt > envelope.json
```

There's a catch: `result` is still a string. If you asked the model for JSON, that JSON sits as text inside the JSON envelope. So you parse twice, and the second parse gets its own step (04).

## 03 · Retry only what's actually transient

On June 9, 2026 the merger failed with `stream idle timeout`. Nothing was broken. The stream just stalled. The fix: the wrapper retries with backoff, but only on a closed list of transient errors. A usage policy refusal won't pass on the second try. Neither will a blocking hook. We had a refusal two days earlier, on June 7. Retrying those just burns time and hides the problem.

This small loop, together with the JSON repair, closed three production incidents for us. Here's roughly what the wrapper looks like:

```python title="shared/anthropic_cc.py"
import json, os, subprocess, time
from shared.json_repair import extract_json

TRANSIENT = ("stream idle timeout", "overloaded", "529", "ECONNRESET", "timed out")

def run_claude(prompt: str, model: str = "sonnet", attempts: int = 3, timeout: int = 600):
    env = {k: v for k, v in os.environ.items() if not k.startswith("CLAUDE_CODE_")}
    for i in range(attempts):
        try:
            p = subprocess.run(
                ["claude", "-p", "--output-format", "json", "--model", model],
                input=prompt, capture_output=True, text=True, timeout=timeout, env=env,
            )
            try:
                envelope = json.loads(p.stdout)
            except json.JSONDecodeError:
                envelope = {}
            if p.returncode == 0 and envelope and not envelope.get("is_error"):
                return extract_json(envelope.get("result", "")), envelope
            err = f"{p.stderr} {envelope.get('result', '')}"
        except subprocess.TimeoutExpired:
            err = "timed out"
        if i == attempts - 1 or not any(t in err for t in TRANSIENT):
            raise RuntimeError(f"claude -p failed: {err[:300]}")
        time.sleep(10 * 2 ** i)
```

Note the `env`: that's the cleanup from section 01. Also note that `envelope` is returned to the caller, so the agent can log `total_cost_usd`.

## 04 · JSON repair: not your fault, still your problem

Even with "Return ONLY JSON" in the prompt, you'll sometimes get markdown fences, a trailing comma before `}`, or an opening sentence. On August 7, 2026 Claude started putting a remark about audit rules it saw in its context in front of the JSON. Our parser didn't know what to do with it. We tried `--bare` to silence it, and that broke subscription auth. So the fix lives on our side. We strip fences, cut from the first bracket to the last, and remove trailing commas. If it still doesn't parse, we raise an exception. We never return `{}`.

```python title="shared/json_repair.py"
import json, re

def extract_json(text: str):
    t = re.sub(r"^`{3}(?:json)?\s*|\s*`{3}$", "", text.strip(), flags=re.M)
    starts = [i for i in (t.find("{"), t.find("[")) if i != -1]
    if not starts:
        raise ValueError("no JSON in model output")
    end = max(t.rfind("}"), t.rfind("]"))
    body = re.sub(r",\s*([}\]])", r"\1", t[min(starts):end + 1])
    return json.loads(body)  # fails loudly, never returns {}
```

Why is this in `shared/`? On May 31, 2026 we fixed a JSON repair bug and found it had several copies in different agents. One of them stayed unpatched. Since then no agent keeps its own parser. A small aside: the prompt that wrote the draft of this post includes a line telling the model not to put audit-rule remarks before the JSON. That's not paranoia. It's a scar.

## 05 · The hook that blocked the merger

On September 9, 2026 the merger produced nothing. The machine had a managed hook on `UserPromptSubmit`. It blocked the prompt because the prompt contained `![Image](url)` style embeds from markdown we'd scraped through Jina. In headless mode there's nobody to click "approve". The hook decides, and the run carries on without you.

There are two things to do. First, know that `claude -p` loads the same settings and hooks as the interactive session, including managed settings you didn't write. Run it once by hand, as the same user and from the same directory the cron uses, and see what gets loaded. Second, clean external input before it goes into the prompt. For us that's one line before every call: `re.sub(r"!\[[^\]]*\]\([^)]*\)", "", text)`. Markdown images have no business in a prompt that summarizes news.

What this block looked like from the outside, and why the cycle summary table marked it green, is exactly what part 2 is about.

## 06 · Timeouts, sleep and caffeinate

Before the 38 minutes, there was a morning when the pipeline took about 2.5 hours. It normally finishes between 06:40 and 06:55. The first suspect was the model: tokens, concurrency, rate limits. We measured. tavily alone ran in 172 seconds, and 8 parallel `claude -p` calls came back in 6 seconds. The model was fine.

The `pmset` log told the story. The Mac was on battery with a 120-second sleep timer, and it fell asleep 43 seconds after cron launched the run at 06:07. The agents hung on sockets until about 08:00. An open lid doesn't mean an awake machine.

The timeout in `subprocess.run` didn't save us. A sleeping machine doesn't run the code that's supposed to check whether time is up. The fix: `local-cycle.sh` re-runs itself under `caffeinate`.

```bash title="local-cycle.sh"
if [ -z "$CAFFEINATED" ]; then
  export CAFFEINATED=1
  exec caffeinate -dimsu "$0" "$@"
fi
```

One more thing for Mac users: there's no GNU `timeout`. Don't wrap commands in `timeout 600` inside the shell script, because it will just fail. Put the timeout in the Python code, and put caffeinate on top of everything.

> **My take:** Half the time we spent on "Claude is slow" was really a DevOps question about a laptop on battery. Before you switch models or cut concurrency, open `pmset -g log`. I'd rather have a slow model on an awake machine than a fast model on a sleeping one.

## Takeaways

- Every `claude -p` call goes through one wrapper. That way a fix lands once, not ten times.
- Always use `--output-format json`, and log `total_cost_usd` for every call. That's how you'll know if the subscription still pays off.
- Retry on a closed list of transient errors. A refusal or a hook block stops immediately.
- A parser that fails raises an exception. A silent `{}` is the most expensive bug you can have in a pipeline.
