במרץ 2026 מישהו ב-Skelpo פתח תיקייה ריקה, הריץ בה Claude Code וכתב לו משפט אחד: תשחזר כמה שיותר מהקוד של עצמך. קלוד מצא שתי התקנות של עצמו, חבילת npm בגרסה 2.1.56 ובינארי של 183MB, ועשה מה שהוא עושה הכי טוב: פיצל. ארבעה subagents יצאו במקביל, ובסך הכול שבעה. שניים סירבו לפרק את קלוד. ה-agent הראשי קרא להם "shy" והמשיך בלעדיהם. בסוף היו על הדיסק 12,093 שורות קוד משוחזר.

אני לא מביא את זה בשביל הצחוק. אלה בדיוק השאלות של החלק הזה: מה מפצלים, מי רואה איזה context, ומה חוזר לסשן הראשי. בחלק הקודם סגרנו מה הולך ל-hook ומה ל-skill. עכשיו עבודה במקביל: plan mode, subagents, git worktrees, ו-handoff של שלוש שורות שחוסך יותר מכל השאר.

## 01 · plan mode לפני שמפצלים משהו

משימה שלא הבנתם אי אפשר לפצל. אז קודם כל: Shift+Tab פעמיים בתוך הסשן, או ישר מהטרמינל:

```bash title="terminal"
claude --permission-mode plan
```

במצב הזה קלוד קורא קבצים, מחפש ומחזיר תוכנית, בלי לכתוב לדיסק. Ctrl+G פותח את התוכנית ב-editor שלכם. זה טקסט, תערכו אותו לפני שהוא נהיה קוד.

הכלל שלי: plan mode לכל שינוי שנוגע ביותר מקובץ אחד, ולא לטרוח על תיקון של שורה. ועוד טריק מהפוסט Claude Code as a Daily Driver ממאי 2026: תפתחו סשן שני, נקי, ותבקשו ממנו לבקר את התוכנית כמו staff engineer. אין לו את ההיסטוריה של הראשון, אז הוא לא מתאהב בה.

בתוכנית שחוזרת אליכם תבדקו דבר אחד: שכל משימה מסומנת תלויה או עצמאית. העצמאיות הן המועמדות לפיצול. כל השאר נשאר בסשן אחד, וזה בסדר גמור.

## 02 · להחליט אם בכלל צריך subagent

רגע, לפני שמגדירים agents, המספרים. אנטרופיק פרסמו ביוני 2025 איך בנו את Research: agent ראשי על אופוס 4 שמפעיל subagents על סונט 4. על ה-eval הפנימי שלהם זה ניצח agent בודד של אופוס 4 ב-90.2%. יפה. אבל באותו פוסט: agent שורף בערך פי 4 טוקנים משיחה רגילה, ומערכת multi-agent בערך פי 15. והם כותבים במפורש שברוב משימות הקוד יש הרבה פחות חלקים שבאמת אפשר להריץ במקביל מאשר במחקר.

המשפט שמסביר למה זה עובד כשזה עובד:

> "The essence of search is compression: distilling insights from a vast corpus."
> — Anthropic, How we built our multi-agent research system

בגדול: subagent שווה את הכסף כשהקלט שלו רעש והפלט שלו תקציר. grep על כל הריפו, לוג של build שנפל, הרצת טסטים, מיפוי של מודול שלא תחזרו אליו. ה-docs אומרים את זה כמעט מילה במילה: כשמשימת צד תציף את השיחה בתוצאות חיפוש, לוגים או קבצים שלא תסתכלו עליהם שוב.

מתי לא: עריכה שצריכה את כל מה שהסשן הראשי כבר יודע. ה-subagent מתחיל מאפס, קורא שוב את אותם קבצים, ואתם משלמים פעמיים. וזה אף פעם לא חינם: הוא שולח בקשות משלו, והן נספרות באותן מגבלות שימוש כמו הסשן הראשי. ועוד משהו לזכור: ה-Explore וה-Plan המובנים מדלגים על CLAUDE.md. הם לא מכירים את הכללים שכתבתם בחלק הראשון, אז אל תתנו להם להחליט על קוד.

## 03 · subagent אחד שבודק, לא עשרה שכותבים

Metabase פרסמו באפריל 2026 איך בנו עשרה subagents ל-500 אלף שורות Clojure. כל אחד הוא קובץ markdown של 2,000 עד 3,000 טוקנים, בערך 150 שורות, באותו מבנה: ידע על הדומיין, איפה הקוד, איך חוקרים, מלכודות, איך בודקים. אבל שם יש גבולות ברורים, query processor של 68 שלבים ו-18 דיאלקטים של SQL. אתם תתחילו באחד. והאחד הכי משתלם הוא זה שבודק:

```markdown title=".claude/agents/test-runner.md"
---
name: test-runner
description: Runs the test suite after code changes and reports only failures. Use after every edit.
tools: Bash, Read, Grep, Glob
model: haiku
---
You run tests and report. You never edit files.

1. Run: npm test 2>&1 | tail -n 200
2. For each failure: file:line, the failing assertion, one-line probable cause.
3. If everything passes, answer exactly: ALL GREEN (<n> tests).
4. Never paste full stack traces. Max 15 lines in total.
```

תשימו לב לשלושה דברים. ב-tools אין Edit ואין Write, אז הוא לא יכול "לתקן" טסט כדי שיעבור. model: haiku, כי להריץ טסטים ולסכם כישלונות לא צריך אופוס. ופורמט פלט קשיח, כי כל שורה שהוא מחזיר נכנסת ל-context הראשי. את npm test תחליפו בפקודת הבדיקה מהחלק הראשון.

איך רואים שזה עובד: /agents מציג אותו ברשימה. אחרי עריכה קלוד אמור להעביר אליו לבד לפי ה-description, ואם לא, תכתבו use the test-runner subagent. ה-description קצר בכוונה: כל ה-descriptions יחד נטענים לכל סשן, ומעל 15,000 טוקנים Claude Code מזהיר כבר בהפעלה. הפירוט הולך לגוף הקובץ, שנטען רק כשה-agent רץ.

> **הדעה שלי:** ה-subagent הכי שימושי הוא לא המומחה, הוא הבודק. agent שכותב קוד במקביל מייצר עוד diff שמישהו צריך לקרוא. agent שמריץ טסטים ומחזיר 15 שורות חוסך לכם את הקריאה.

ואם haiku עדיין יקר לכם, יש כבר Show HN בשם Rayline שמנתב subagents למודלים זולים יותר או מקומיים. לא ניסיתי אותו בפרודקשן.

## 04 · worktree לכל סשן שעורך קוד

subagent הוא פיצול בתוך סשן. כשרוצים שני סשנים מלאים שכל אחד כותב קוד, הם לא יכולים לשבת באותה תיקייה: שינויים נדרסים, ה-git status של שניהם מעורבב, וטסט של אחד נופל בגלל קובץ חצי-ערוך של השני. git worktree פותר את זה בלי clone נוסף: אותו .git, תיקייה וענף נפרדים לכל סשן.

```bash title="parallel.sh"
# from the main checkout
git worktree add ../app-auth -b feature/auth
git worktree add ../app-billing -b fix/billing-rounding

# gitignored files do not come along
cp .env ../app-auth/ && cp .env ../app-billing/
echo "PORT=3001" >> ../app-auth/.env
echo "PORT=3002" >> ../app-billing/.env

# one terminal per worktree
cd ../app-auth && claude
cd ../app-billing && claude

git worktree list

# after the PR is merged
git worktree remove ../app-auth
git branch -d feature/auth
```

ב-git worktree list תראו שורה לכל תיקייה: נתיב, commit וענף. ויש שלוש מלכודות שנופלים בהן ביום הראשון. קודם כל, קבצים ב-.gitignore לא מגיעים: .env, node_modules, וגם CLAUDE.local.md מהחלק הראשון. CLAUDE.md ו-.claude/settings.json כן מגיעים, כי הם ב-git. חוץ מזה, שני dev servers על אותו port, ובשביל זה ה-PORT ב-.env של כל worktree. והשלישית זה אתם. שלושה סשנים במקביל זה שלושה PRs לקרוא, ונראה לי ששלושה זה הגבול לפני שה-review שלכם נהיה צוואר הבקבוק. את ה-review תעשו בסשן חדש מה-main, לא בזה שכתב את הקוד.

## 05 · סשן חדש לכל משימה, ו-handoff בשלוש שורות

תפתחו שיחה חדשה לכל משימה. שיחה ארוכה עולה יותר בכל הודעה וגם עונה פחות טוב: כל turn שולח מחדש את כל ה-context, וכל ניסיון כושל שנשאר שם ממשיך למשוך את המודל לאותו כיוון. /compact מסכם, אבל הוא בוחר לבד מה חשוב. אני מעדיף לבחור בעצמי.

לפני /clear, זו הבקשה האחרונה בסשן:

```text title="prompt"
Write HANDOFF.md in three lines: what works, what is open, what failed and why. No other text.
```

ומה שיוצא נראה ככה:

```markdown title="HANDOFF.md"
מה עובד: login עם Google עובר end-to-end, 42 טסטים ב-auth/ ירוקים.
מה פתוח: refresh token לא מתחדש אחרי 60 דקות. לא התחלתי.
מה נכשל: middleware ב-edge runtime נשבר על crypto. לא לחזור לשם.
```

ואז /clear, ובסשן החדש: @HANDOFF.md נמשיך מהשורה השנייה. השורה השלישית הכי חשובה. בלעדיה הסשן הבא ינסה בדיוק את אותו middleware, יגיע לאותה שגיאה, וישרוף לכם חצי שעה. בפועל: HANDOFF.md אחד בכל worktree, ב-.gitignore. ו-claude --continue שמור למשימה שנקטעה באמצע, לא למשימה הבאה.

## מה לקחת

- plan mode לכל שינוי שנוגע ביותר מקובץ אחד, וסשן שני ונקי מבקר את התוכנית.
- subagent רק כשהקלט רעש והפלט תקציר. בלי Edit, עם haiku, עם פורמט פלט קשיח.
- סשן שעורך קוד מקבל worktree משלו, .env משלו ו-port משלו.
- לפני /clear: מה עובד, מה פתוח, מה נכשל. השורה האחרונה היא זו שחוסכת את הכסף.
