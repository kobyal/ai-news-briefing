## September 9, 06:07

On 2026-09-09 at 06:07, launchd woke the Mac and ran `local-cycle.sh`, as it has every morning since May. It's a graph of about 10 agents. There are sources, a merger that combines everything into one briefing, a publish step, and finally a QA evaluator that runs on what's already live on the site. A normal day ships about 11 stories. That's by design, not a bug.

The merger is the heavy step. One `claude -p` call, on the subscription, that gets everything the agents collected. That includes the full text of articles we read through Jina. What comes back is JSON with `news_items`.

In the previous part we covered how we wrap that call: retries, JSON repair, and why you don't retry a hook block. This time the story is what happens when all that wrapping works exactly as designed, and the result is still empty.

## The summary email was all green

A bit before seven, the summary email arrived. A table with one row per step, and success in every row. The merger finished, publish finished, the files went up to S3.

Except today's briefing had 0 stories.

Every layer reported the truth about itself. The process exited with rc=0. The `claude -p` output was valid JSON, with `subtype: "success"`. The wrapper saw no transient error, so it didn't retry. Publish got a valid structure and uploaded it. Nobody lied. Nobody asked the one question that matters either: did anything come out?

Salesforce, who built a monitoring system for Agentforce, call this deceptive green metrics. Ours were literally green, in a table, in an email.

Eliot Ferstl of Pandocore wrote on August 13 about a completely different bug: a Kubernetes label put on the Deployment instead of the pod template. But his line describes this morning exactly:

> It's an easy mistake to ship because nothing anywhere tells you it didn't work.

## First fix: the August bug

On August 5, 6 and 7 we'd already had empty briefings. There, `claude -p` put a paragraph of commentary before the JSON, the parser returned `{}`, and the RSS and editorial agents shipped empty briefings. The exact same symptom.

So I went straight to JSON repair. I checked the parser, ran it on the raw output, looked for a preamble. There wasn't one. There was nothing to repair, because `result` had no briefing content at all.

Fine, rerun just the merger. Also empty. That's when I realized I was fixing the previous bug, not this one.

> **My take:** The most expensive mistake in a postmortem is recognizing a familiar symptom. "Empty briefing" looked the same in three incidents we had between June and September, and each time the cause was somewhere else. Since then I start from the raw fields, not from memory.

## num_turns=0

The field that told the whole story was `num_turns`. Zero. The model didn't answer badly. It didn't answer at all, because it never saw the prompt.

The machine runs a `UserPromptSubmit` hook configured at the machine level (managed), not in our repo. Per Anthropic's docs it runs "When you submit a prompt, before Claude processes it". The hook saw image embeds in the article text in the `![Image](url)` format, which is exactly what Jina returns, and blocked. And `claude -p` reported the block like a finished turn: rc=0, success, zero turns.

That's defect one. The second was our fail path. On July 14 we moved all agents to `agents/active/`. One branch in the merger's failure code wasn't updated and still wrote to the old path. The result: a `merger-agent/` directory at the repo root. A shadow directory. From then on, later runs found it, and the merger just didn't run. No error, no red line in the log, for every run after, until someone deletes it by hand.

The third defect was trusting the summary table. It measures whether a process exited, not what it produced.

In short: a hook that blocks silently, a CLI that reports a block as success, and a fail path that left a landmine. Each one alone was a small bug. All three together were a morning with no briefing.

## What we check after every call now

The new rule is simple: an LLM call's success is measured by content, not exit code. Every call goes through the same gate in `shared/`, because copy-pasting checks like these across agents has already cost us outages.

```python title="assert_llm.py"
import json
from pathlib import Path


class SilentFailure(RuntimeError):
    pass


def assert_llm_result(raw: str, *, floor: int, key: str = 'news_items') -> dict:
    env = json.loads(raw)  # claude -p --output-format json
    if env.get('is_error'):
        sub = env.get('subtype')
        raise SilentFailure(f'is_error, subtype={sub}')
    if env.get('num_turns', 0) < 1:
        raise SilentFailure('num_turns=0: the model never saw the prompt (hook block?)')
    text = (env.get('result') or '').strip()
    if not text:
        raise SilentFailure('rc=0 but result is empty')
    payload = json.loads(text)  # after your JSON repair step
    items = payload.get(key) or []
    if len(items) < floor:
        raise SilentFailure(f'{key}={len(items)} below floor {floor}')
    return payload


def assert_no_shadow_dirs(repo: Path) -> None:
    stray = sorted(p.name for p in repo.glob('*-agent') if p.is_dir())
    if stray:
        raise SilentFailure(f'pre-migration agent dirs at repo root: {stray}')
```

Note the order. `num_turns` before the parse, because a hook block leaves nothing to parse. The floor goes last. Roughly speaking, a polite usage-policy refusal and a swallowed preamble both end up in the same place: a valid structure with an empty list. The floor catches both without knowing what happened, and that's exactly what we want from it.

The QA evaluator that runs after publish is a second layer, not a replacement. It has a floor per agent: minimum item count, how old the file is, whether the Hebrew arrays are parallel to the English ones. Below the floor is P0, even when every step said success. And `assert_no_shadow_dirs` runs at the start of the cycle, before the first agent, not after something has already been skipped.

It's boring. It's also the only thing that would have caught September 9 at seven in the morning.

rc=0 means the process exited. Not that anything happened.
